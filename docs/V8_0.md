# V8.0 Base-Trusted Merge Root

V8.0 moves the required merge-authorization root off pull-request-controlled workflow code and onto `pull_request_target`, whose workflow definition is loaded from the protected base branch.

The trusted root never checks out or executes the pull request head. It runs protected merge-policy tests from `main`, polls 16 authoritative `pull_request` workflows for the exact PR head SHA, validates the live `main-production-gate` Ruleset, writes exact-head evidence, obtains GitHub OIDC-backed provenance, verifies that provenance, and uploads the trusted merge-root evidence.

The compatibility mirror still maps the other 16 workflow names to the repository Ruleset's required status contexts, but it no longer emits `v75-merge-authorization`. That context is now owned directly by the base-trusted root.

Security boundary: source workflows still execute code from the PR head. The base-trusted root does not trust their textual output; it requires their exact-head GitHub workflow conclusions and independently verifies server policy/provenance. Future policy can further restrict changes to critical workflow definitions.
