# V9.4 Journaled Recovery Executor

V9.4 closes the V9.2/V9.3 integration gap around external recovery mutations.

Before any injected recovery mutation runs, the executor persists a V9.3 `PREPARED` record bound to the exact PR head, workflow/job identity, replay key, owner, lease key, action and attempt. The mutation must return `accepted=true` plus a stable `receipt_id`; only then does V9.4 transition the record to `COMMITTED`.

If the process crashes, the transport fails, the mutation is rejected, or the receipt is missing after `PREPARED`, the journal intentionally remains unresolved. A later worker fails closed instead of blindly replaying the action. This narrows duplicate-side-effect risk but does not claim exactly-once behavior from external providers unless the downstream gateway also honors an idempotency key.

V9.4 remains exact-head bound and has no merge authority. It does not bypass repository policy, alter required checks, or write to `main` directly.
