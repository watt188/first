# V8.1 Base-Trust Canary

This documentation-only change is an intentional canary for the V8.0 merge-root architecture.

A successful merge proves the post-bootstrap path on an ordinary new pull request: the required `v75-merge-authorization` context is produced by the protected-base `pull_request_target` workflow, all 16 authoritative pull-request workflows must succeed for the exact head SHA, the live server Ruleset must remain strict and bypass-free, and the exact-head merge-root evidence must be attested and provenance-verified before merge.

The canary does not alter application or policy code.
