# V10.6 Recovery HTTP Transport

V10.6 adds a minimal HTTP transport above the V10.5 secure production recovery service.

It exposes only `GET /v1/health` and `POST /v1/command`. The command route accepts the V10.3/V10.4 authenticated envelope and delegates it unchanged into the secure service, so HMAC verification, replay protection, key lifecycle policy, exact-head checks and recovery convergence remain authoritative below the transport.

The transport enforces JSON framing, a bounded request body, no-store responses, explicit method/route allowlists and fail-closed command rejection. The built-in server binds to loopback by default; binding a non-loopback address requires explicit opt-in.

V10.6 does **not** implement TLS termination, mutual TLS, reverse-proxy trust, rate limiting, distributed replay consensus, remote secret distribution, hardware-backed key custody or provider-independent exactly-once physical side effects. A production internet-facing deployment must place this service behind an independently configured authenticated TLS boundary or a later version that adds one.
