# V6.6 PEP Hardening

V6.6 hardens the Policy Enforcement Point used for model-driven side effects.

## Guarantees

- Role-aware path policies for `frontend`, `backend`, and `test` writers.
- Exact allowlist enforcement with default deny.
- Absolute paths and `..` traversal are denied.
- Existing symlink targets and symlink parent components are denied.
- Writes use a same-directory temporary file, fsync, and atomic `os.replace`.
- Every write records before/after SHA-256 evidence and byte count.
- Multi-file transactions preflight every operation before any write.
- Transaction success returns a SHA-256 manifest for every committed path.
- Audit events are written as JSON Lines under `artifacts/pep-v66-audit.jsonl`.

## V6.5 integration target

The new PEP removes the V6.5 workaround where the test specialist had to write using the `backend` role. A subsequent integration commit will bind Chief of Staff V6.5/V6.6 orchestration to explicit `backend` and `test` role policies.
