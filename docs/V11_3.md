# V11.3 Truthful Failure Classification

V11.3 hardens the live resident recovery worker after the V11.2 canary proved durable PREPARED/COMMITTED journaling and real GitHub rerun dispatch.

The canary also exposed an unsafe simplification in V11.2: the worker supplied a synthetic `transport_timeout_or_network` marker to the classifier. That made every eligible provider-facing workflow failure look transient even when the real failure was a deterministic test defect.

V11.3 removes that shortcut. Before any mutation it now reads the actual failed jobs for the triggering workflow run, downloads bounded job logs, and passes the observed evidence into `AutonomousRecoveryV82`. Only evidence classified as a retryable provider transient may reach the durable mutation gateway. Permission, policy, code/test, evidence, or ambiguous failures fail closed without a rerun.

The worker keeps the V11.2 guarantees: exact PR-head binding, first-attempt-only eligibility, durable PREPARED/COMMITTED journal state, lookup by logical recovery key, and no claim of provider-level physical exactly-once. GitHub's rerun API still does not accept a caller-supplied idempotency key, so the durable gateway provides at-most-once dispatch from our control plane and explicitly reports `physical_exactly_once: false`.

The superseded V11.1 observer workflow is removed to avoid duplicate workflow_run consumers. The resident workflow keeps its existing path but is renamed `v113-resident-recovery` and executes the V11.3 worker from `main`.
