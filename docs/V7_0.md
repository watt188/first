# V7.0 Production Convergence

V7.0 converges the previously separate production controls behind one runtime entry point.

## Unified commands

- `python -m production_runtime.v70 status`
- `python -m production_runtime.v70 preflight`
- `python -m production_runtime.v70 deliver`
- `python -m production_runtime.v70 verify`

## Release contract

A production delivery is accepted only when all of the following are bound into one path:

- Chief of Staff orchestration (V6.5)
- role-aware PEP writes (V6.6)
- provider resilience (V6.7)
- isolated generated-code execution (V6.8)
- commit-bound evidence integrity (V6.9)

`deliver` runs the real Chief-of-Staff acceptance flow, requires production provider configuration, seals the resulting evidence against `PRODUCTION_SOURCE_SHA`, immediately verifies the manifest, and writes a final V7.0 production report.

## Provenance

CI binds `PRODUCTION_SOURCE_SHA` to the pull request head SHA rather than the synthetic pull-request merge commit. The uploaded artifact contains the generated implementation, generated/fallback tests, acceptance evidence, integrity manifest, and V7.0 report.

## Boundary

V7.0 is a convergence/release contract. It does not claim a kernel-grade sandbox, distributed circuit breaker, hardware-backed signature, or external transparency log. Those remain separate hardening layers.
