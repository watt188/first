# V8.6 Recovery State Reconciliation

V8.6 closes the recovery time-of-check/time-of-use gap by reconciling the V8.5 append-only recovery evidence ledger with the current exact-head GitHub failure snapshot before another recovery decision can proceed.

The reconciliation gate verifies the V8.5 hash chain and PR/head binding, rejects stale PR heads, rejects ledger jobs that are no longer failed, rejects workflow identity changes, and rejects new untracked failures once recovery evidence already exists. An empty ledger is allowed only as the initial live failure snapshot.

V8.6 is deliberately non-authoritative for merge and policy. It does not rerun jobs, request rework, merge, bypass the server Ruleset, alter required checks, or write to `main`. Recovery mutations remain delegated through the V8.3/V8.4 layers and final merge authority remains base-trusted/server-enforced.
