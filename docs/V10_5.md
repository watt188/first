# V10.5 Secure Production Recovery Service

V10.5 composes the V10.1 durable recovery service, V10.2 strict command surface, V10.3 HMAC/replay boundary and V10.4 rotating key policy into one production-facing single-host assembly.

## Guarantees

- Durable SQLite runtime, pending-action, authentication metadata and replay-nonce state.
- Strict `health` / `recover` command boundary inherited from V10.2.
- HMAC-SHA256 authenticated envelopes with durable replay protection.
- Key activation, retirement, revocation and overlapping rotation windows.
- HMAC secrets remain caller-supplied in memory and are not intentionally persisted by the authentication metadata databases.
- Storage integrity is checked before secure service readiness is returned.
- Exact-head and fail-closed recovery semantics remain delegated to the V10.0/V10.1 runtime.

## Storage layout

The service owns a root containing a `runtime/` directory plus separate `authentication_keys.sqlite3` and `authentication_nonces.sqlite3` databases. Separation prevents accidental state/journal/key/nonce table coupling.

## Limits

This remains a single-host security and durability profile. It does not provide TLS termination, remote secret distribution, hardware-backed key custody, distributed replay consensus, multi-host key-rotation coordination, or exactly-once physical effects when a downstream provider does not durably honor its idempotency key.
