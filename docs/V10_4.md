# V10.4 Authentication Key Rotation

V10.4 adds a durable authentication-key lifecycle above the V10.3 HMAC command envelope.

The SQLite keyring persists only key identifiers and lifecycle metadata (`not_before`, retirement, revocation, generation). HMAC secrets are injected at process start and are never intentionally persisted by the keyring. Multiple keys can overlap during a rotation window. A retired key may verify an in-flight envelope that was signed before the retirement cutover and still passes the V10.3 clock-skew limit, but it can no longer sign new commands. Revocation is immediate at or after the configured revocation timestamp.

The rotation layer reuses the V10.3 durable nonce store, so replay protection remains effective across process restarts and key transitions. Unknown keys, unavailable secret material, invalid lifecycle transitions, expired envelopes and revoked keys fail closed.

## Threat model and limits

This is a single-host metadata store and HMAC trust model. It does not distribute secrets, provide hardware-backed key custody, implement TLS, coordinate rotation across multiple hosts, or provide distributed replay consensus. Production deployments should inject secrets from an external secret manager and use transport security. Exactly-once physical recovery side effects still depend on downstream idempotency semantics.
