# V11.1 Resident Recovery Worker

V11.1 introduces a repository-resident `workflow_run` observer for selected provider-facing workflows. It continuously watches completed runs on `main`, accepts only first-attempt `failure` / `timed_out` events tied to exactly one pull request, validates the run identity and lowercase 40-character head SHA, and writes an auditable recovery-candidate artifact.

## Safety boundary

V11.1 intentionally does **not** call GitHub's `rerun-failed-jobs` mutation endpoint. That endpoint does not accept a caller supplied idempotency key and the GitHub-hosted runner filesystem is ephemeral, so the repository cannot honestly satisfy V10.9's durable-idempotency plus lookup-by-key contract with a simple Actions-only implementation.

The worker therefore reports `mutation_performed=false` and `requires_durable_gateway=true`. This is a fail-closed boundary rather than a capability downgrade disguised as production readiness.

## Loop prevention

Only the first workflow attempt (`run_attempt == 1`) is eligible, and only the provider workflow allowlist is observed. CI and worker workflows are not eligible, preventing a recovery observer loop.

## Next production step

A subsequent deployment can connect this observer to a durable gateway backed by a persistent store or service that can atomically claim an idempotency key, execute the provider mutation, and later resolve the same key to the same receipt. Only after that contract is live should automatic GitHub mutation be enabled.
