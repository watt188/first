# V10.2 Production Recovery Command Surface

V10.2 adds a strict JSON-compatible operational command boundary above the V10.1 durable production service.

## Operations

- `health`: read-only readiness and storage-integrity status.
- `recover`: one exact-head recovery request delegated to V10.1/V10.0.

## Safety properties

- Unknown command fields are rejected.
- Recovery identity fields are type-checked and exact-head SHA values must be lowercase 40-character hex.
- `expected_head_sha` must equal `current_head_sha` before the service is called.
- Arbitrary method names, executable payloads and secret-bearing extension fields are not accepted.
- A recovery command succeeds only when the underlying service returns `PRODUCTION_RECOVERY_CONVERGED`.
- JSON output is canonicalized for stable machine consumption.

## Boundary

V10.2 is an application command adapter, not a network transport. Authentication, process supervision, TLS and remote transport remain deployment concerns. V10.1 remains a single-host SQLite durability profile; exactly-once physical effects still require a downstream provider that durably honors the idempotency key contract.
