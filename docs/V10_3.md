# V10.3 Authenticated Command Envelope

V10.3 adds an authenticated application boundary above the strict V10.2 recovery command surface.

## What it adds

- HMAC-SHA256 authentication over a canonical JSON command envelope.
- Explicit `key_id`, timestamp and nonce binding.
- Constant-time signature comparison.
- Durable SQLite nonce claims that survive process restarts.
- Configurable clock-skew rejection for stale envelopes.
- Fail-closed replay protection: a nonce is consumed before the delegated command executes, so an ambiguous downstream failure cannot be retried by replaying the same signed envelope.
- Canonical machine-readable JSON output.

## Envelope

The only accepted top-level fields are:

- `key_id`
- `timestamp`
- `nonce`
- `payload`
- `signature`

The signature is HMAC-SHA256 over `key_id`, timestamp, nonce and the canonical JSON payload.

## Security boundary

V10.3 authenticates callers that already possess a shared secret. It does not provide TLS, remote key distribution, secret rotation orchestration, an HTTP server, user identity federation, or distributed replay consensus. The SQLite replay store is a single-host durability profile. Those concerns belong to the deployment/transport layer.

Secrets must be supplied by the runtime environment or secret manager. They must never be committed to the repository.
