# V9.2 Recovery Transaction Engine

V9.2 composes the protected recovery stack into one durable execution path.

## Transaction sequence

1. Load or initialize exact-head recovery state.
2. Acquire a V8.9 recovery lease and persist it with V9.0/V9.1 compare-and-swap semantics.
3. Derive the next bounded recovery decision from V8.2.
4. Authorize the logical action through the V8.8 replay guard.
5. Execute one V8.7 recovery session.
6. Persist the accepted V8.5 evidence ledger with compare-and-swap.
7. Release the lease and persist the final state.

## Guarantees

- stale PR heads fail before recovery mutation;
- competing active leases fail before recovery mutation;
- duplicate logical replay is rejected;
- recovery attempts advance monotonically;
- accepted recovery evidence is durably persisted;
- state generation advances under CAS;
- merge authority remains outside the transaction engine.

A residual crash window still exists if the process dies after the external recovery mutation is accepted but before its evidence state is committed. The lease prevents immediate concurrent replay until expiry; a write-ahead pending-action journal is the next hardening step.
