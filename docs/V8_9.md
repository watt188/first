# V8.9 Recovery Lease Guard

V8.9 closes the concurrent-recovery race that remains after the V8.8 replay guard.

## Goal

Only one logical recovery worker may hold an active lease for a given PR exact head at a time. A second worker must fail closed instead of racing the first worker and issuing a duplicate mutation.

## Guarantees

- exact-head binding for every lease;
- deterministic SHA256 lease identity;
- idempotent reacquisition by the same owner + nonce;
- active lease rejection for competing workers;
- expired lease takeover only after expiry;
- owner-bound renew and release operations;
- tampered lease rejection;
- deterministic tests bound into the existing required `ci` context.

The caller supplies monotonic integer time and must persist leases using compare-and-swap semantics in its transport. V8.9 itself does not mutate GitHub, merge pull requests, bypass the server Ruleset, change required checks, or write to `main`.
