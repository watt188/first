# V9.8 Recovery Runtime Supervisor

V9.8 introduces a single restart-safe runtime entry point above V9.6 and V9.7.

## Routing

1. Validate exact PR head.
2. Read durable recovery state and derive the next attempt, recovery decision and replay key.
3. If no journal record exists, delegate to the normal V9.6 idempotent recovery transaction.
4. If a journal record is PREPARED, do not replay the mutation. Reconcile only through the V9.5 downstream idempotency lookup, then repair evidence and lease state through V9.7.
5. If a journal record is COMMITTED, call V9.7 directly; no external mutation is issued.
6. ABORTED records, active foreign leases, stale heads, journal identity mismatches and unresolved provider lookups fail closed.

## Result

The recovery runtime can now be restarted after a crash and choose a safe continuation path from durable state instead of relying on process-local knowledge.

## Boundary

V9.8 provides restart-safe logical recovery only when the downstream provider implements the V9.5 durable idempotency lookup contract. It does not claim exactly-once physical effects for providers that cannot prove the prior request outcome. SQLite remains a single-host durability backend, not distributed consensus.
