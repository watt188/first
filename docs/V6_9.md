# V6.9 Evidence Integrity

V6.9 makes evidence artifacts self-verifying and commit-bound instead of relying on ordinary JSON/JSONL alone.

## Guarantees

- Every evidence file is hashed with SHA-256.
- Every manifest entry includes path, byte count, file digest, previous-entry hash, and its own entry hash.
- Entries form an ordered hash chain with a deterministic chain head.
- The manifest itself has a SHA-256 over canonical JSON.
- The manifest is bound to the pull-request head SHA through `source_sha`.
- Verification rejects modified files, modified manifest entries, broken chain links, missing files, unsafe paths, and source-SHA mismatch.
- Existing V6.5 multi-agent evidence is sealed and verified before artifact upload.
- A dedicated V6.9 workflow emits and uploads a sealed proof artifact.

## Boundary

This detects accidental or post-generation modification inside the artifact set and binds the manifest to the source commit supplied by CI. It is not a cryptographic signature and does not defend against an attacker who can rewrite both the files and the trusted CI workflow/source-of-truth. Stronger provenance would require an external signing identity or transparency service.

## Verification

`tests/test_evidence_integrity_v69.py` checks clean verification, file tampering, manifest tampering, source SHA mismatch, path traversal rejection, and seal/readback behavior.
