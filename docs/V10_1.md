# V10.1 Production Recovery Service

V10.1 turns the V10.0 recovery runtime into a single-host production service bootstrap.

## What it adds

- Owns durable SQLite recovery-state and pending-action journal files under one service root.
- Validates the downstream recovery gateway contract at startup.
- Runs SQLite integrity preflight before serving recovery requests.
- Exposes one exact-head `run()` entry point backed by V10.0 audit-before / converge / audit-after semantics.
- Preserves state and journal data across process restarts.
- Fails closed on stale heads, invalid gateway contracts, invalid storage roots, storage corruption, and non-converged runtime results.

## Boundary

This is a durable single-host production profile. SQLite is not distributed consensus. Exactly-once physical external effects still depend on a downstream gateway that durably honors the V9.5 idempotency lookup contract. V10.1 does not claim otherwise.
