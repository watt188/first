# V8.2 Autonomous Recovery & Rework Loop

V8.2 adds a fail-closed recovery policy for protected autonomous delivery.

Failures are classified into bounded categories before any action is taken:

- transient provider/infrastructure failures may rerun failed jobs within a strict attempt budget;
- deterministic code/test failures and evidence inconsistencies request autonomous rework;
- policy drift, permission failures, exhausted retry budgets, and ambiguous failures escalate to a human;
- no recovery path may bypass the server Ruleset, required checks, evidence binding, or merge root.

The V8.2 deterministic tests are attached to the already-required `ci` context, so recovery-policy regressions block merge.
