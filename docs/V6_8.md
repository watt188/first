# V6.8 Execution Isolation

V6.8 moves generated-code acceptance out of the main Python process and into a bounded child process.

## Guarantees

- Generated feature and test code execute in a temporary isolated working directory.
- Child Python runs with isolated mode (`-I`) and site initialization disabled (`-S`).
- Child environment is explicitly rebuilt and does not inherit model provider secrets.
- Wall-clock timeout is enforced by the parent process.
- On POSIX runners, address-space, CPU, core-dump, and open-file limits are applied before execution.
- Child stderr is never surfaced in acceptance evidence.
- Acceptance evidence records isolation settings and contract-check results.

## Scope

This is process isolation, not a kernel/container security boundary. It materially reduces accidental or model-generated side effects escaping into the orchestrator process, but it is not a replacement for OS/container sandboxing against a determined hostile payload.

## Verification

`tests/test_execution_isolation_v68.py` verifies successful isolated execution, timeout termination, provider-secret stripping, and sanitized child failures.
