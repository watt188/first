# V8.7 Recovery Session Coordinator

V8.7 composes the protected recovery primitives introduced in V8.2-V8.6 into one fail-closed recovery session.

The coordinator performs recovery state reconciliation immediately before any mutation, delegates at most one bounded recovery action to the V8.4 orchestrator, then appends only an accepted single-failure receipt to the V8.5 exact-head evidence ledger and verifies the resulting chain.

Safety properties:

- exact PR head required before any recovery action;
- live state must reconcile with the existing recovery ledger;
- only one recovery action may be delegated per session invocation;
- rejected gateway receipts do not produce evidence;
- ambiguous multi-failure escalation is not forged into a single-failure ledger entry;
- stale heads, tampered ledgers, changed/resolved tracked failures, and new untracked failures fail closed;
- V8.7 cannot merge, bypass repository rules, alter required checks, or write to main.

The deterministic V8.7 acceptance tests run inside the already-required `ci` context.
