# V10.0 Production Recovery Convergence

V10.0 turns the V9.x recovery stack into one production-facing exact-head entry point.

## Contract

1. Derive the exact logical recovery action and attempt from durable state.
2. Run the V9.9 read-only audit before any mutation.
3. Fail closed on terminal-aborted or active foreign-lease states.
4. Delegate safe execution/reconciliation to the V9.8 restart-safe runtime.
5. Re-audit the exact same logical action after execution.
6. Return success only when the post-audit state is `CONVERGED`.

## Guarantees

The facade preserves exact-head binding, durable CAS state, lease exclusion, replay identity, write-ahead journaling, downstream idempotency lookup, append-only evidence and restart reconciliation. It does not weaken any lower-layer fail-closed condition.

## Boundary

`PRODUCTION_RECOVERY_CONVERGED` proves logical convergence of the recovery protocol for one exact-head action. It does not by itself prove exactly-once physical effects when a downstream provider cannot durably enforce or report idempotency. The current SQLite persistence layer is single-host durability, not distributed consensus.
