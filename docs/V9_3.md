# V9.3 Pending Action Journal

V9.3 closes the V9.2 crash window by persisting a write-ahead recovery intent before any external recovery mutation is executed.

## State machine

`PREPARED → COMMITTED` when an accepted external receipt is durably reconciled with recovery evidence.

`PREPARED → ABORTED` only when the action is explicitly abandoned after reconciliation.

## Guarantees

- pending actions are exact-head bound;
- replay key, owner and lease identity are persisted before mutation;
- only one `PREPARED` action may exist per PR/head;
- identical prepare calls are idempotent;
- conflicting replay-key reuse fails closed;
- pending records survive process restart;
- tampered action hashes fail closed;
- a restart can detect unresolved `PREPARED` work and must not blindly replay it;
- COMMITTED/ABORTED transitions use the prior action hash as a CAS-style precondition.

V9.3 itself does not execute the external mutation, merge pull requests, bypass repository rules, or write to `main`. V9.4 will integrate the journal into the durable recovery transaction engine and reconcile unresolved prepared actions before any new mutation.
